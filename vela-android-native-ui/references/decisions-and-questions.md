# 选择项与成本询问

先读取需求与现有实现。首版不添加装饰动效与过渡。若用户明确要求信息跑马灯，将单行 `<marquee>` 作为可读性功能直接实现，不再询问。只有用户未说明且新增动效会改变工作范围时才澄清；不要把已定事项重新抛给用户。

## 动画成本估算

| 类型 | 难度 | 估算耗时 | 估算 AI token | 备注 |
|---|---|---:|---:|---|
| 简单透明度/颜色状态过渡 | 低 | 0.5–1.5 小时 | 3k–8k | 需确认 SDK 样式动画支持和耗电 |
| 页面切换/滑入 | 中 | 2–4 小时 | 8k–18k | 与系统返回手势冲突风险，需设备验证 |
| 自定义环形/连续动画 | 高 | 4–10 小时 | 18k–40k | 刷新率、功耗、边缘裁切与生命周期工作量高 |
| 多页面统一动效和无障碍降动效 | 高 | 1–3 天 | 40k–100k | 按页面数和目标 SDK 上下浮动 |

这些是 AI 实施估算而非报价或确定承诺。仅在用户主动提出额外装饰动效、且类型/范围仍不清楚时，向用户说明难度、估算耗时和验证成本。不得因此阻塞已明确要求的文字跑马灯。

## 必须按需澄清的可选项

- 跑道屏手环首页固定单列；其他形态由 AI 按内容和有效宽度选择单列或双列，无需为列数询问用户，也不增加列数切换设置。单列图标是可选的视觉处理，默认不加，确有留白需要时先做标题宽度预算。
- 若页面有可能出现空列表、无搜索结果或尚无记录，默认显示本 Skill 的主题化 `empty-state`；只有确实不需要空状态或需要品牌专属插图时才询问。
- 是否需要横幅、底部导航或装饰图标等？按应用场景逐项询问，避免全加。
- 控件展示 Demo 的设置页保持精简；一般应用只加入需求所需的业务设置，不擅自添加无线、网络或点击计数等系统项。
- 是否需要额外装饰动画？默认不添加；用户已经要求的文字跑马灯直接实现，不重复询问。
