# Vela 工程、编译与交付检查

## 工程要求

- 纯英文路径；`package.json` 必须 UTF-8 无 BOM。
- `manifest.json` 声明 `package/name/versionName/versionCode/minPlatformVersion/deviceTypeList/icon/config.designWidth/router`。确认目标 Vela SDK 对字段类型的版本要求；不要照抄未经验证的旧版字段。
- 本仓库按目标形态提供相互独立的项目目录：`demos/runway-band9`、`demos/runway-band10`、`demos/square`、`demos/circle`。跑道屏工程不加入方屏/圆屏专用 CSS 或媒体规则；方屏和圆屏各改各的源目录、分别编译。Band 9/10 的结构相同，但分别有目标设备工程与产物。
- 使用 AIoT IDE/Toolchain 的实际 release 打包命令。规格提醒 `aiot build` 只提示、不产 RPK；不得把它算作成功。具体命令按已安装工具版本 `--help` 和 IDE 工程配置核验。
- 模拟器调试可以 debug；实际设备安装使用公版 release。没有签名资格/发布凭据时只能产出源码或未签名包并明确说明，不能谎称公版包可安装。

## 验收清单

- [ ] 控件 Demo 的所有详情都有真实可操作控件；首页点分类进入对应列表。一般应用按主要用户流程逐页检查。
- [ ] 8主题×3模式都可选；纯黑保持强调色。
- [ ] 控件展示 Demo 的设置页只含字号、主题与一行关于；一般业务应用的设置按需求选择。字号档位须按需求实现，只缩放指定正文角色，固定角色（时间、页面标题、控件/按钮标签、导航、计数等）不随字号改变；受影响控件几何需同步检查。
- [ ] storage 恢复设置；坏数据可回退默认。
- [ ] 跑道屏手环首页始终单列；其他形态按内容可读性选择单列或双列。纵向列表本身仍使用可滚动原生列表，设置入口随列表滚动并带安全尾行。
- [ ] 圆屏的顶部栏、标题、卡片、列表视口、底部控件都完整位于中心安全区；不能出现标题消失、首行左右边缘被圆形裁掉、控件贴圆周的情况。双列只有在每列的标题和说明仍可读、整张卡片均在安全区时使用，否则改单列。
- [ ] 矩形宽屏按实际 viewport 校验字号和文本宽度；同一角色字号保持一致，不能因为设计宽度或页面缩放造成时间、页面标题、卡片标题明显变大或说明文字截断。
- [ ] 控件展示 Demo 的页面顶部只有时间；不加无关装饰动画；用户明确要求的文字跑马灯正常滚动且字号不是默认 30px。
- [ ] 左滑返回在页面根处理；二级页不重复显示返回首页按钮；逐页验证不白屏。
- [ ] 全部字号统一到 10/11/12/14/16/18/20/24px 角色阶梯；同角色跨页和设备相等，媒体查询不得擅自缩字号。22/24/26 偏好只映射为 10/11/12px 并作用于获准的长说明。标题宽度预算可读，文字不被时间区遮挡。
- [ ] 三个形态工程在相应模拟器编译/运行；Band 9/10 在设备上运行验证。
- [ ] release 产物存在且 RPK 内容/签名状态已验证。

## 路由与主题回归清单

- 控件 Demo 依次点击首页全部分类；每页标题、条目数、内容 ID 与该分类一致，不能全部回落到第一类。一般应用逐一走通主要路由与关键业务状态。
- 依次打开各类首个详情，确认详情标题和实际渲染的组件符合路由 `id`。
- 逐一选择 8 个主题，观察首页、分类列表、详情、设置四处的页面背景色调、卡片表面、选中态与强调色均同步变化；浅色画布与卡片/按钮表面都带所选主题的浅色调，暗色画布/卡片/按钮表面为可辨识的主题深色调，纯黑画布严格 #000000 且所有控件表面不是纯黑。
- 对首页、分类列表、设置列表截图取样卡片中心、上下边缘的 RGB；一个列表项背景应是连续单色，禁止宿主与内层背景叠画造成横向“三明治”色带。确认 RPK 中 `<list-item>` 宿主确实带动态 `surface`，内部布局节点透明；只看到子 face 有背景或像素高度相等不算通过。设置选项卡必须在源码中明确绑定 surface，不能只有尺寸/圆角样式。
- 分别选择浅色、暗色、纯黑；确认背景、卡片表面、文字对比度正确，纯黑模式背景严格为 `#000000`。
- 设置页修改主题后返回，确认恢复页面立刻应用新值；重启应用后设置仍存在。
- 使用原生 list 的页面要逐项滑到列表底部；确认尾部有至少 24–32px 安全留白，最后一项与关于行完全露出黑边/圆角裁切区。检查跑马灯首屏/重复模板确实滚动，而不是被省略号截断。检查文本是否被固定高度裁切、卡片是否超出滚动视口、主题/模式选项是否全部可达。逐个操作 radio、switch、slider、stepper、color-picker、font-adjuster、segmented-control、chip、dialog 和 bottom-nav，确认状态回显。检查 marquee 确实启动。重点在模拟器/设备看字形裁切与圆屏安全区；只通过静态构建或 RPK 检查不能声称交互和显示已通过。

- 圆屏截图专项：完整显示时间和页面标题；检查首屏最左/最右卡片边缘、首行/末行、状态栏和圆周之间的距离；截取顶部、中段、底部，确认每个高度位置的内容都没有穿出圆形可用弦宽。若网格任一行触碰圆弧或文本被裁，切到单列后重新截图复核。
- 宽屏文字专项：读取渲染后 CSS 字号与运行时 viewport，确认首页时间/主标题使用约定角色值；长说明使用明确字号的单行 marquee 或可读换行，不允许静态裁掉句首/句尾。
- 对照 2026-10-11 的设备截图经验：圆屏首页发生过顶部标题几乎消失、首行左右卡片被圆弧裁切；矩形 Redmi Watch 截图出现文字比例偏大和说明截断。回归检查必须分别覆盖圆形裁切与矩形字体宽度，不能用其中一种形状的截图代替另一种验证。


- 复核首页、分类、详情、设置及全部组件：相同角色字号与 `settings-and-typography.md` 一致；不存在 9/13/15/17/19px 等临时档、圆屏字号覆写、巨大跑马灯默认字、裁切或状态值溢出。
